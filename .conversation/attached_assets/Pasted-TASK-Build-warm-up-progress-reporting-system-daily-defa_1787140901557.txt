TASK: Build warm-up progress reporting system — daily default with weekly opt-out, delivered by email + dashboard, with contextual upsell alerts for other IndexFlow engines during the warm-up period.

WHAT THIS DOES:
Every Cold Email server in warm-up (days 1-28) gets a progress report showing warm-up status. Default cadence is DAILY. Client can switch to WEEKLY via a one-click toggle. Reports go out by email AND appear as a dashboard card. During warm-up, dashboard also shows contextual upsell alerts pointing to other engines (Listening, AI Chatbot, Voice Agent) that pair naturally with an about-to-launch cold email campaign.

CONTEXT:
- Warm-up cycle is 28 days (matches the bonus trial extension already built)
- Server provisioning, warm-up tracking, and blocklist monitoring already exist in the codebase — find the relevant tables/services (likely something like mail_servers, warmup_status, or similar)
- Client dashboard already exists — find where server status is currently shown

BUILD FOUR THINGS:

1. DATABASE — add reporting preference field
   - Add a column to the workspace or server settings table: report_frequency, type enum('daily', 'weekly'), default 'daily'
   - Add last_report_sent_at timestamp to track when the last report went out per server

2. BACKEND — warm-up report generator (scheduled job)
   - Runs daily via cron/scheduled job
   - For each server currently in warm-up (day 1-28):
     - Check report_frequency for that workspace
     - If 'daily': generate and send report every day
     - If 'weekly': only generate and send if 7+ days have passed since last_report_sent_at (or if it's day 1, 7, 14, 21, 28)
   - Report content per day/week: current day number out of 28, percentage complete, brief status (e.g. "warming normally", "engagement building", "no issues detected"), estimated days remaining
   - Send via existing email system (find the email sending method already used for other transactional emails)
   - Also write the same report data to a table the dashboard can query (e.g. warmup_reports) so the dashboard card always shows the latest status without waiting for the next email

3. FRONTEND — dashboard warm-up card
   - Show a progress card on the server's dashboard page during warm-up: progress bar (day X of 28), status text, "next report: today/in X days"
   - Add a small toggle or link: "Switch to weekly updates" (if currently daily) or "Switch to daily updates" (if currently weekly) — one click, updates report_frequency immediately, no confirmation modal needed for this one (it's low-stakes)

4. FRONTEND — contextual upsell alerts during warm-up
   - While a server is in warm-up (day 1-28) AND the workspace hasn't already used/enabled the relevant engine, show rotating dashboard alerts:
     - "Your server is warming up — get a head start. Try Listening Engine to find prospects before your first send."
     - "Set up your AI Chatbot now so it's ready when your campaigns launch and replies start coming in."
     - "Configure Voice Agent to handle inbound calls generated by your cold email replies."
   - Show ONE alert at a time, rotate every few days, dismissible per alert (don't show the same dismissed one again)
   - Alerts link directly to the relevant engine's setup page
   - Track which alerts have been shown/dismissed per workspace so they don't repeat

RULES:
- Daily is the default — no explicit opt-in required, it just starts
- Weekly is opt-in via the one-click toggle — never default to weekly
- Reports are informational only — no action required from the client
- Upsell alerts are contextual to warm-up specifically — they should stop showing once warm-up completes (day 28)
- Don't show an upsell for an engine the workspace has already configured/enabled
- Wrap all report generation and email sending in try/catch — a failed report must never block warm-up progress tracking itself
